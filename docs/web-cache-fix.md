# Обновление веб-версии без смешивания файлов

Проверено на `main` после PR #12 (`0ffaae5d36cf43163248728329e21ce6f79758de`).
Публичный адрес: https://ksnarchive.github.io/little-village-shop/.

## Причина

На момент проверки `build-info.json` указывал правильный merge-коммит, свежий
`index.pck` содержал `start.scn`, `character_creator.scn` и новые ресурсы.
Чистая загрузка публичной версии прошла frontend-проверки WebKit.
Стартовая сцена в `project.godot` — `res://scenes/start.tscn`, аргументы веб-запуска
пусты. Само наличие сохранения не запускает магазин: требуется «Продолжить».

Однако HTML, JS, WASM и PCK публиковались по постоянным URL (`index.*`).
У всех четырёх ответов Pages был `Cache-Control: max-age=600`. Проверка деплоя
читала свежий `build-info.json?sha=...` и лишь искала название в HTML; она не
проверяла реально загружаемые игровые ресурсы. Зелёный workflow поэтому не
исключал старый PCK в кеше браузера/CDN рядом с новой HTML-оболочкой.

Смешанная загрузка воспроизведена в WebKit с профилем iPhone 13: HTML/WASM/JS
публичной версии PR #12, ответ `index.pck` заменён настоящим Web release из
`8db2c11` (main перед PR #12). Нового меню/гардеробной нет; после запуска прежней
игры виден магазин без экранных кнопок. `body.className === 'touch frontend'`,
`#movement` имеет `display: none`. Touch определён правильно. Новая оболочка
скрывает кнопки до `window.setFrontend(false)`, а старый PCK этот вызов не знает.
Это объясняет связанные симптомы. Кеш конкретного физического iPhone недоступен;
его содержимое не предполагается проверенным напрямую.

## Исправление

`tools/package_release.py` после экспорта создаёт один набор `index.<commit>.*`:
HTML, JS, WASM, PCK, audio worklet и изображения. Меняется и `config.executable`,
иначе Godot продолжил бы получать WASM/PCK по старым URL.

Стабильный `index.html` содержит встроенный загрузчик. Он получает
`build-info.json` с `cache: 'no-store'` и новым query для обхода CDN и переходит к HTML текущего коммита.
Даже закешированный загрузчик выбирает текущую версию. Версионный HTML повторяет
проверку **до загрузки движка**: перезагрузка старой страницы направляет в новую.
После выбора сборки адрес возвращается к корневому URL: закладки и reload
остаются действительными после обновлений. Возврат из back/forward cache проверяет версию через reload. Ошибка проверки
показывает сообщение и оставляет запуск заблокированным; старые файлы молча не
запускаются. PWA и service worker не используются.

Путь каталога и origin не меняются. `/userfs`, IndexedDB, имя проекта, схема
сохранений и игровые сцены не изменяются. Кеши/сохранения не очищаются.
Сенсорное определение `maxTouchPoints || pointer: coarse` уже корректно;
изменять механику или принудительно показывать кнопки поверх меню не требуется.

Публикуется только `main`. После деплоя workflow сверяет SHA-256 реальных
версионных HTML/JS/WASM/PCK и остальных ресурсов с манифестом сборки.

У старого HTML, полученного **до этого исправления**, ещё нет нового загрузчика.
При первом переходе можно дождаться его прежнего 10-минутного срока кеша либо
один раз открыть корневой URL с новым query, например `/?update=<commit>`.
Удалять данные Safari или сохранения не нужно. Последующие обновления защищены
новым загрузчиком.

## Проверка

```sh
GODOT_BIN=/path/to/godot-4.3 bash tests/run_checks.sh
godot --headless --path . --export-release Web builds/web/index.html
python3 tools/package_release.py builds/web "$(git rev-parse HEAD)" --ref local
python3 -m http.server 8060 --directory builds/web
# В другом терминале:
cd web
npm ci
npx playwright install --with-deps chromium webkit
npm test
```

- Godot 4.3: 894 проверки, 0 ошибок; импорт, smoke-test стартовой сцены и release-экспорт.
- `frontend.cjs`: профиль iPhone (Safari UA, mobile, touch, DPR 3), меню, настройки,
  вход/отмена гардеробной, имя/внешность, портретная компоновка, магазин и Continue.
- `smoke.cjs`: экранные кнопки, движение, рюкзак/пауза, сохранение, Continue,
  портретный и малые горизонтальные экраны.
- `cache-upgrade.cjs`: настоящий HTTP-кеш WebKit с `max-age=600`, одна origin и
  IndexedDB, переход между двумя наборами версионных URL при закешированном HTML.
  Проверяет запрос новых JS/WASM/PCK, отсутствие запросов старых/неверсионных
  файлов, сохранность **всех байтов** IndexedDB, отмену редактора, Continue,
  закешированный корневой загрузчик и отказ проверки версии без запуска движка.
  PCK в двух версиях этой регрессии одинаков: проверяется именно обновление
  ресурсов и сохранность прогресса, независимо от изменения игровых механик.

WebKit на Linux с эмуляцией iPhone не является проверкой физического iOS Safari
или его экранной клавиатуры. Скриншоты CI сохраняются в `browser-validation`.
