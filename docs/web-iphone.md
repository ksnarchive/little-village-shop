# Веб-версия для iPhone

Исходная ветка: `stage-8-cozy-shop`, коммит
`b187800eaea9ce6aa1fdbd80cb8841b8314e34b9` (интерьер PR #8).
Отдельная ветка веб-версии: `web-iphone-safari`. Слияние PR #8 и веб-PR не требуется
для сборки этой ветки и не выполняется автоматически.

## Как играть

После успешной публикации откройте сайт в **обычной вкладке Safari** на iPhone,
поверните телефон горизонтально, отключите блокировку поворота в Пункте управления
и нажмите **«Играть»**, затем **«Новая игра»** или **«Продолжить»**.
Нужен Safari с WebAssembly и WebGL 2; рекомендуется актуальная iOS.
Установка Godot и компьютер не нужны. Полноэкранный режим и установка на домашний
экран не требуются.

Слева — четыре кнопки движения; удерживайте нужную стрелку. Можно одновременно
удерживать две стрелки для диагонали. Справа — контекстная кнопка с названием действия возле предмета,
**I** (рюкзак), **Esc** (пауза/закрыть окно). Нажимайте кнопки внутри игрового окна
пальцем. Меню закупок и полок прокручиваются вертикально, если ряд не помещается.
Кнопки стоят за пределами игрового поля и не закрывают мебель, HUD или меню.
На компьютере работают прежние WASD/стрелки, E/I/Esc и мышь.

Начните с закупки у стола справа или бесплатных товаров в мятном сундуке слева:
подойдите спереди, нажмите E. В сундуке **«Взять 1»** переносит товар в рюкзак.
У полки **«Выложить»** выставляет выбранное количество. После 09:00 придут покупатели;
у кассы внизу слева нажмите E, затем **«Обслужить»**.

**Сохранение:** дождитесь выхода всех посетителей, нажмите Esc → **«Сохранить игру»**.
Это прежнее правило игры: посетители и неоплаченные корзины не сохраняются.
Автосохранение выполняется при новой игре, итогах дня и начале следующего утра.
Сохранение `user://village_save.json` и резервная копия хранятся в IndexedDB этого
браузера. После сообщения об успехе дайте странице несколько секунд для записи,
затем можно закрывать вкладку. «Продолжить» восстанавливает прогресс после перезагрузки.
Очистка данных сайта удаляет прогресс; другой браузер/устройство имеет отдельный слот.
Приватные вкладки и запрет хранилища не подходят для надёжного продолжения.
Облачной синхронизации нет. Схема сохранения и игровые механики не изменены.

## Включение GitHub Pages с iPhone

У подключённого GitHub-приложения нет административного разрешения для включения Pages
(проверенная попытка вернула `403 Resource not accessible by integration`).
Настройку выполняет владелец репозитория; терминал не нужен.

1. В Safari откройте https://github.com/ksnarchive/little-village-shop/settings/pages
   и войдите как владелец репозитория. Если интерфейс тесный, в меню страницы Safari
   выберите «Запросить настольный веб-сайт».
2. В **Build and deployment → Source** выберите **GitHub Actions**.
   Не выбирайте Deploy from a branch и не объединяйте PR ради публикации.
3. Откройте **Settings → Environments → github-pages**. Если в **Deployment branches
   and tags** разрешена только `main`, добавьте `web-iphone-safari` как разрешённую
   ветку (**Selected branches and tags → Add deployment branch or tag rule → Branch**).
   Уже существующие правила для `main` оставьте. Если стоит **No restriction**, менять
   ничего не нужно. При ручном подтверждении окружения одобрите ожидающую публикацию.
4. Откройте **Actions → Web build and GitHub Pages**, выберите последний запуск
   для ветки **web-iphone-safari**. Если он завершился ошибкой на шаге настройки Pages,
   нажмите **Re-run jobs → Re-run failed jobs**. Если сборка ещё идёт — дождитесь её.
   Новый workflow в ветке до слияния может не показывать кнопку **Run workflow**;
   повторный запуск уже существующего запуска работает без слияния.
5. Дождитесь зелёных **build** и **deploy**, включая **Verify public build matches this
   commit**. Только после этого адрес сайта можно считать проверенным.
   Откройте адрес из deployment **github-pages**.

Ожидаемый адрес после успешной публикации: `https://ksnarchive.github.io/little-village-shop/`.
Это адрес назначения, а не утверждение о доступности сайта. Текущее состояние
публикации и ограничения проверки записаны в PR и `docs/validation.md`.

## Сборка и проверка для разработчиков

- Официальные **Godot 4.3** и export templates **4.3.stable**; preset `Web`.
- Compatibility / WebGL 2, `variant/thread_support=false`, без GDExtension, PWA,
  service worker и требований SharedArrayBuffer/COOP/COEP. Все URL относительные,
  поэтому файлы работают в `/little-village-shop/` на GitHub Pages.
- Web использует фиксированный viewport 640×360. Nearest, lossless/no mipmaps и
  snapping сохранены. CSS использует nearest scaling; при достаточном месте выбирает
  целый физический масштаб без существенного уменьшения поля. На тесных экранах
  масштаб дробный с резкими краями: возможны неравные ширины пикселей, размытия нет.
  Учитываются `safe-area-inset-*`, dynamic viewport height и поворот экрана.
- WebGL-контекст заранее создаётся с multisampled **буфером вывода**: это устраняет
  наблюдавшийся в Linux WebKit конфликт attachment при Emscripten swap. Внутренняя
  игровая графика остаётся без MSAA, сглаживания текстур или CSS-интерполяции.
- Pointer Events и capture поддерживают несколько пальцев; cancel, потеря capture,
  фокуса, скрытие страницы и поворот отпускают виртуальные клавиши. Кнопки посылают
  прежние события клавиатуры в canvas, без второго пути игровых транзакций.
- При нажатии «Играть» начинается загрузка, есть progress и сообщение об ошибке.
  PWA-кеш не используется, чтобы старая сборка не скрывала новое оформление.

```sh
bash tests/run_checks.sh
mkdir -p builds/web
godot --headless --path . --export-release Web builds/web/index.html
python3 -m http.server 8060 --directory builds/web
# В отдельном терминале, только для разработчиков:
cd web
npm ci
npx playwright install --with-deps chromium webkit
npm test
# Дополнительный длинный сценарий с реальным посетителем:
npm run test:gameplay
```

Workflow `.github/workflows/web-pages.yml` запускает все проверки Godot, экспорт,
браузерную проверку загрузки, управления и сохранений Chromium/WebKit, сохраняет screenshots/logs и артефакт Pages.
PR только проверяется; push в `web-iphone-safari` публикует проверенную ветку.
Push в `main` публикует её лишь после явного слияния пользователем.
`build-info.json` содержит точный SHA и базу интерьера; deployment сравнивает его
с SHA текущего запуска после публикации. Никакие PR не объединяются workflow.

Оба режима браузерных проверок используют настоящий release export, нажатия и удержания кнопок,
обычные меню, реальных посетителей и содержимое IndexedDB; игровых debug-хуков нет.
В `npm test` проверяются экранные кнопки, ручное сохранение, перезагрузка, Continue и размеры
портретного/горизонтального экрана. `npm run test:gameplay` дополнительно проверяет
закупку, переносы, полку и продажу. Этот длинный сценарий использует распознавание
спрайта и зависит от перекрытия персонажей и времени визитов; успешный полный CI-прогон
для неизменённого игрового кода: [461d7d8](https://github.com/ksnarchive/little-village-shop/actions/runs/45276534925).
В обязательный шаг публикации входит короткий сценарий вместе со всеми 529
проверками логики/сцен Godot. Linux WebKit — близкая проверка движка, **не iOS
Safari**: Apple GPU, память iPhone, системные жесты, экранная панель Safari и выгрузка
вкладок требуют отдельного испытания на устройстве.


Новый визуальный стиль, размеры управления и актуальные скриншоты описаны в
[pastel-redesign.md](pastel-redesign.md).
