# iPhone Safari: намеренный ввод имени и восстановление viewport

Ветка `fix/ios-keyboard-viewport` создана от актуальной `main` (`986aedc`,
включая уже объединённый PR #14). Godot **4.3.stable.official.77dcf97d8**.

## Причины и границы воспроизведения

`start_menu.gd` вызывал `creator.name_input.grab_focus()` сразу после создания
редактора. Поэтому переход по пользовательскому нажатию на «Новую игру» мог
сам активировать HTML-поле виртуальной клавиатуры. В исходной release-сборке
на мобильном WebKit действительно наблюдался `document.activeElement = INPUT`
без отдельного нажатия на имя.

Godot 4.3 динамически создаёт `input`, `textarea` и невидимый contenteditable
IME-прокси внутри `#screen`. Первые два полагались на браузерный размер шрифта;
IME явно получал inline `font-size: 1px`. В Linux WebKit обычные прокси в этой
проверке имели 16px, а IME — 1px. Это **не** воспроизведение автоматического
увеличения на физическом iOS: браузерные значения по умолчанию и поведение
экранной клавиатуры различаются. Теперь CSS гарантирует 16 CSS px всем трём
типам прокси **до** вызова `focus()`, независимо от шрифта Godot, DPR и CSS-масштаба
canvas. Размер менее 16px является известным условием focus zoom в iOS Safari.

Прежняя оболочка подгоняла canvas по layout viewport и слушала только обычные
resize-события. Она не учитывала уменьшение/смещение visual viewport при
клавиатуре и панелях Safari, а выбор логической ориентации делала через
`innerHeight > innerWidth` отдельно в JS и Godot.

## Изменения

- При входе фокус получает кнопка подтверждения, а не `LineEdit`. Поле имени
  остаётся доступным для намеренного нажатия и ввода. Сам редактор, его список
  вариантов, валидация имени и виртуальная клавиатура Godot не переписаны.
- `input`, `textarea` и contenteditable-прокси Godot получают `font-size:16px
  !important`; правило переопределяет также inline 1px у IME.
- `#layout` и стартовый экран размещаются в доступной области
  `visualViewport.width/height/offsetLeft/offsetTop`. Подгонка canvas по-прежнему
  использует прежние размеры 400×740 / 640×360 и nearest-фильтрацию.
- Прокси `input`/`textarea` фиксированы относительно viewport, поскольку Godot
  задаёт им координаты из `canvas.getBoundingClientRect()`. После изменения
  доступной области их прямоугольник синхронизируется с canvas; значение,
  выделение и фокус не меняются.
- Обработаны `visualViewport.resize/scroll`, обычный resize, ориентация,
  focusin/focusout и pageshow. Пересчёт объединяется через animation frame.
  После focusout есть повторный пересчёт через 350ms для позднего завершения
  анимации закрытия клавиатуры. Новые обработчики viewport не вызывают focus/blur.
- JS и Godot используют общий `window.isGamePortrait()`: на сенсорном устройстве
  ориентация берётся из Screen Orientation / старого `window.orientation`, а
  не из уменьшенной клавиатурой высоты. Для обычного окна ПК остаётся media query.
- Сохраняются `env(safe-area-inset-*)`, минимальные поля 4px; подсказка поворота
  привязана к доступной области. Панели браузера исключены размерами visual
  viewport, вырез и домашний индикатор — CSS-полями safe area.
- Viewport meta не изменяется: не добавлены `user-scalable=no`, maximum-scale
  или minimum-scale. Скрипт не сбрасывает масштаб, не прокручивает страницу
  принудительно и не компенсирует намеренное увеличение уменьшением игры. При
  намеренном zoom используются layout-размеры, чтобы поворот не сохранял старый
  прямоугольник экрана.

Проверено отсутствие изменений в графике и её генераторах, `character_creator.gd`,
`character_appearance.gd`, поезде и монологе, сохранениях, торговле, WAV,
`release-guard.js` и `package_release.py`. Три существующих браузерных сценария
теперь намеренно нажимают поле перед набором имени вместо зависимости от бага.
Кеширование, URL, origin и `/userfs` сохранены.

## Регрессионные проверки

`tests/run_character_tests.gd` проверяет фокус не-текстовой кнопки при входе.
Полный Godot-runner: **1014 проверки, 0 failures**.

`web/ios-keyboard.cjs` запускает реальный single-threaded release-экспорт в
мобильном WebKit и проверяет:

1. Отсутствие DOM-фокуса ввода при открытии редактора; ввод открывается только
   после нажатия поля, в том числе повторного после blur.
2. CSS-шрифт всех реально созданных Godot input/textarea/IME не менее 16px.
3. Ввод кириллического имени через настоящий HTML-прокси и сохранение его в
   IndexedDB после подтверждения персонажа.
4. Изменение и смещение видимой области с моделью поднятой клавиатуры,
   включая scroll-событие без window resize, явные safe-area-поля и отсутствие
   случайной смены логической ориентации.
5. Совпадение прямоугольника прокси с canvas и восстановление полного canvas
   после blur, даже при позднем изменении размеров без resize-события.
6. Отсутствие ограничений в viewport meta и противодействия намеренному zoom,
   включая поворот во время увеличения без устаревших размеров и повторного ввода.
7. Переход редактор → поезд, отсутствие устаревшего фокуса, портретные и
   альбомные размеры 390×844, 844×390, 375×667, 667×375 и 844×300.

Фикстура VisualViewport находится **только в тесте** (`addInitScript`).
Она не добавляет отладочных API в игру и не меняет игровое состояние.
Скриншоты результата сохраняются в `builds/browser-checks/` и загружаются
существующим CI как browser-validation artifacts.

```sh
GODOT_BIN=/path/to/godot-4.3 bash tests/run_checks.sh
mkdir -p builds/web
godot --headless --path . --export-release Web builds/web/index.html
python3 tools/package_release.py builds/web "$(git rev-parse HEAD)" --ref refs/heads/fix/ios-keyboard-viewport
python3 -m http.server 8060 --directory builds/web
cd web
npm test
# Только новая регрессия:
npm run test:ios-keyboard
```

## Ограничения и проверка на физическом устройстве

Playwright WebKit на Linux — не iOS Safari. Профиль iPhone задаёт UA, touch,
DPR и размеры, но **не открывает системную клавиатуру Apple, не воспроизводит
её автоматический zoom и реальные аппаратные safe-area-insets**. Реальные
DOM-фокус, CSS, resize и переходы проверены; перекрытие/панорамирование клавиатурой
и ненулевые safe-area-поля моделируются. Финальная проверка исходной проблемы
требует физического iPhone.

Для приёмки в обычной вкладке Safari:

1. Открыть новую игру в обеих ориентациях: имя не активировано, клавиатуры нет.
2. Нажать имя, набрать текст, закрыть клавиатуру системной кнопкой, повторить ввод.
   Страница не должна самопроизвольно увеличиваться; после закрытия виден весь UI.
3. Повернуть телефон при вводе и после закрытия, показать/скрыть панели Safari.
   Проверить нижнюю кнопку, края canvas, вырез и домашний индикатор.
4. Подтвердить персонажа и перейти в поезд; повернуть телефон ещё раз.
   Изображение и диалог должны целиком помещаться в доступную область.
5. Проверить намеренное браузерное масштабирование: новые запреты и автоматический
   сброс масштаба не вводятся. Существующие обработчики игровых жестов не менялись.

Полный `npm test` прошёл: Chromium/WebKit smoke, редактор/кириллическое имя,
полная поездка с возобновлением, повороты, подтверждение пропуска, возврат в лавку,
cache-upgrade с сохранением IndexedDB и новая мобильная регрессия. Однопоточный
Web release экспортирован и упакован штатным `package_release.py` без ошибок.
